# 会话管理

> Pi 的会话系统支持自动保存、分支、压缩和导出，让你的对话历史井井有条。

---

## 一、会话存储

### 1.1 存储位置

会话自动保存到 `~/.pi/agent/sessions/`，按工作目录组织。

### 1.2 会话格式

会话以 JSONL 格式存储，采用树形结构：

```json
[
  { "id": "a", "parentId": null, "type": "user", "message": "..." },
  { "id": "b", "parentId": "a", "type": "assistant", "message": "..." },
  { "id": "c", "parentId": "b", "type": "user", "message": "..." },
  { "id": "d", "parentId": "c", "type": "assistant", "message": "..." }
]
```

每个条目有 `id` 和 `parentId`，支持在任意点分叉。

## 二、会话命令

### 2.1 创建与恢复

| 命令 | 说明 |
|------|------|
| `/new` | 开始新会话 |
| `/resume` | 浏览并选择历史会话 |
| `/session` | 显示当前会话信息 |

### 2.2 命令行选项

```bash
pi -c                  # 继续最近的会话
pi -r                  # 浏览并选择会话
pi --no-session        # 临时模式（不保存）
pi --session <路径|ID> # 使用指定会话
pi --fork <路径|ID>    # 从指定会话分叉
```

### 2.3 命名会话

```
/name 重构认证模块
```

命名后更容易在 `/resume` 中找到。

## 三、分支系统

### 3.1 使用 /tree

`/tree` 让你在会话树中导航：

```
├─ 用户: "你好，能帮我..."
│  └─ 助手: "当然！我可以..."
│     ├─ 用户: "试试方案 A..."
│     │  └─ 助手: "方案 A 的结果..."
│     │     └─ 用户: "成功了..."  ← 当前活跃
│     └─ 用户: "其实，试试方案 B..."
│        └─ 助手: "方案 B 的结果..."
```

### 3.2 Tree 控制

| 快捷键 | 说明 |
|--------|------|
| ↑/↓ | 导航可见条目 |
| ←/→ | 翻页 |
| Ctrl+←/Ctrl+→ | 折叠/展开或跳转分支 |
| Shift+L | 设置/清除标签 |
| Shift+T | 切换标签时间戳 |
| Enter | 选择条目 |
| Escape/Ctrl+C | 取消 |
| Ctrl+O | 切换过滤模式 |

### 3.3 过滤模式

| 模式 | 说明 |
|------|------|
| default | 默认视图 |
| no-tools | 隐藏工具输出 |
| user-only | 只显示用户消息 |
| labeled-only | 只显示带标签的条目 |
| all | 显示所有 |

### 3.4 选择行为

- **选择用户消息**：移动到该消息的父节点，将消息放入编辑器，可以编辑后重新提交（创建新分支）
- **选择助手/工具消息**：移动到该条目，编辑器为空，可以从这里继续
- **选择根消息**：重置为空对话，将原始提示放入编辑器

## 四、分叉与克隆

### 4.1 /fork

从之前的消息创建新会话文件：

1. 打开选择器
2. 选择要分叉的消息
3. 消息文本放入编辑器
4. 可以编辑后提交，创建新会话

### 4.2 /clone

将当前活跃分支复制到新会话文件：

- 保留完整的活跃路径历史
- 新会话以空编辑器开始

### 4.3 命令行分叉

```bash
pi --fork <路径|ID>
```

从 CLI 直接分叉会话。

### 4.4 对比

| 功能 | /tree | /fork | /clone |
|------|-------|-------|--------|
| 输出 | 同一会话文件 | 新会话文件 | 新会话文件 |
| 视图 | 完整树 | 用户消息选择器 | 当前活跃分支 |
| 典型用途 | 在同一文件中探索备选方案 | 从早期提示开始新会话 | 复制当前工作后继续 |
| 摘要 | 可选分支摘要 | 无 | 无 |

## 五、上下文压缩

### 5.1 手动压缩

```
/compact
/compact 重点关注性能优化
```

### 5.2 自动压缩

当上下文接近窗口限制时，Pi 会自动压缩旧消息。

### 5.3 配置

```json
{
  "compaction": {
    "enabled": true,
    "reserveTokens": 16384,
    "keepRecentTokens": 20000
  }
}
```

## 六、分支摘要

当 `/tree` 切换分支时，Pi 可以摘要被放弃的分支：

1. 选择要切换到的条目
2. Pi 提示是否摘要当前分支
3. 选择摘要方式：
   - 不摘要
   - 使用默认提示摘要
   - 使用自定义焦点摘要

摘要会附加到新位置，保留重要上下文。

## 七、导出与分享

### 7.1 导出为 HTML

```
/export
/export my-session.html
```

### 7.2 分享为 GitHub Gist

```
/share
```

上传为私有 GitHub Gist，生成可分享的 HTML 链接。

### 7.3 分享 OSS 会话

使用 [`badlogic/pi-share-hf`](https://github.com/badlogic/pi-share-hf) 发布到 Hugging Face：

```bash
pi-share-hf
```

---

## 八、会话管理最佳实践

1. **命名重要会话**：使用 `/name` 给会话命名
2. **使用分支探索**：不确定方案时，用 `/tree` 探索不同方向
3. **定期压缩**：长对话使用 `/compact` 释放上下文
4. **导出备份**：重要会话导出为 HTML 备份
5. **利用标签**：在 `/tree` 中用 Shift+L 标记重要节点
