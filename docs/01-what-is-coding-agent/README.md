# 什么是 AI Coding Agent

> 理解 AI Coding Agent 的核心概念，是掌握 Pi 的第一步。

---

## 一、从 Copilot 到 Coding Agent

### 1.1 传统代码补全

```
用户写代码 → 工具补全下一行 → 用户接受/拒绝
```

传统的代码补全是**被动的**：工具根据上下文预测你可能要写的代码，但它不理解你的意图，也不会主动行动。

### 1.2 AI 助手（Chat）

```
用户提问 → AI 回答 → 用户自己实现
```

Chat 模式更进一步，能理解自然语言指令，但它**只能建议**，不能直接操作文件系统。

### 1.3 AI Coding Agent

```
用户下达任务 → Agent 自主规划 → 调用工具执行 → 验证结果 → 继续迭代
```

Coding Agent 是**主动的、自主的**：它能理解任务、制定计划、调用工具（读写文件、执行命令）、验证结果，并根据反馈迭代修正。

---

## 二、Coding Agent 的核心能力

### 2.1 工具调用（Tool Use）

Agent 不只是生成文本，它能**调用真实工具**：

| 工具 | 能力 |
|------|------|
| `read` | 读取文件内容 |
| `write` | 创建或覆盖文件 |
| `edit` | 精确编辑文件（字符串替换） |
| `bash` | 执行 shell 命令 |
| `grep` | 搜索文件内容 |
| `find` | 查找文件 |
| `ls` | 列出目录 |

这些工具让 Agent 能**真正操作你的项目**，而不只是给出建议。

### 2.2 上下文理解（Context）

Agent 能理解：
- **项目结构**：目录布局、文件关系
- **代码语义**：函数逻辑、类设计、模块依赖
- **历史对话**：之前的讨论、已做的修改
- **指令文件**：`AGENTS.md`、`CLAUDE.md` 中的项目规范

### 2.3 自主规划（Planning）

面对复杂任务，Agent 会：
1. 分析任务需求
2. 拆解为子任务
3. 确定执行顺序
4. 并行执行独立任务
5. 验证每步结果

### 2.4 迭代修正（Iteration）

当遇到错误时：
- 分析错误原因
- 尝试修复
- 验证修复效果
- 如果失败，换一种方法

---

## 三、与传统工具的对比

| 特性 | 传统IDE | Copilot | Chat | Coding Agent |
|------|---------|---------|------|--------------|
| 自主执行 | ❌ | ❌ | ❌ | ✅ |
| 文件操作 | 需用户确认 | ❌ | 建议代码 | 自主读写 |
| 命令执行 | ❌ | ❌ | 建议命令 | 自主执行 |
| 上下文理解 | 有限 | 代码级 | 对话级 | 项目级 |
| 多轮迭代 | ❌ | ❌ | 需用户引导 | 自动迭代 |
| 工作流定制 | 插件 | 有限 | 有限 | 完全可扩展 |

## 四、主流 Coding Agent 框架

### 4.1 闭源方案

| 框架 | 特点 |
|------|------|
| **GitHub Copilot** | IDE 集成、代码补全、Chat |
| **Claude Code** | Anthropic 官方、强大但闭源 |
| **Cursor** | IDE 为主、AI 辅助编程 |
| **Codex (OpenAI)** | CLI 工具、云端执行 |

### 4.2 开源方案

| 框架 | 特点 |
|------|------|
| **Pi** | TypeScript、极致可扩展、Monorepo |
| **Aider** | Python、Git 集成、多模型 |
| **OpenHands** | Python、全栈、沙箱执行 |
| **Nanobot** | Python、超轻量、MCP 支持 |

### 4.3 Pi 的差异化

Pi 选择了一条独特的路线：

1. **极致可扩展**：通过 TypeScript 扩展系统，几乎一切都可以定制
2. **不内置特定功能**：没有子 Agent、没有计划模式、没有权限弹窗——因为每个团队的工作流不同
3. **Monorepo 架构**：ai → agent → coding-agent 的分层设计，每层都可独立使用
4. **多模式运行**：交互式、Print、RPC、SDK——适应各种集成场景

## 五、关键概念

### 5.1 Agent Loop（智能体循环）

```
用户输入 → LLM 推理 → 工具调用 → 收集结果 → 继续推理 → ... → 最终回复
```

这是所有 Coding Agent 的核心循环。LLM 根据用户输入和工具结果，决定下一步调用哪个工具，直到任务完成。

### 5.2 Context Window（上下文窗口）

LLM 有固定的上下文窗口大小（如 128K、200K tokens）。Agent 需要：
- 在有限窗口内完成任务
- 当对话过长时进行压缩（Compaction）
- 智能管理上下文使用

### 5.3 Tool Calling（工具调用）

LLM 通过结构化输出声明要调用的工具及其参数：
```json
{
  "tool": "read",
  "parameters": { "path": "src/app.ts" }
}
```

Agent 运行时执行工具并返回结果给 LLM，形成循环。

### 5.4 System Prompt（系统提示词）

系统提示词定义了 Agent 的行为规范：
- 角色定义
- 工具使用说明
- 项目规范（从 AGENTS.md 加载）
- 技能说明（从 Skills 加载）

---

## 六、小结

| 概念 | 说明 |
|------|------|
| **Coding Agent** | 能自主执行代码相关任务的 AI 系统 |
| **Tool Use** | Agent 通过工具操作文件系统和执行命令 |
| **Agent Loop** | LLM 推理 → 工具调用 → 结果收集 → 继续推理的循环 |
| **Context Window** | LLM 的有限记忆空间，需要智能管理 |
| **Extensibility** | Pi 的核心设计理念：一切可扩展 |
